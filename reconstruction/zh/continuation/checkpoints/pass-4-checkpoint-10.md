## Distribution intent — resolved

The project owner established that the English edition is intended to have:

1. **Continuity independent of upstream** — the English project retains its own identity and accumulated experience rather than depending on upstream incorporation.
2. **Additional catchment** — use of the English skill produces new AI experiences which are collected in the English-language project.
3. **A contribution path upstream** — collected experience is tested, selected, translated/adapted and submitted upstream as pull requests.
4. **A route to test installability and functionality** — the English edition is intended to be testable through existing provisioning workflows. This is a future validation objective, not a claim that installation or functionality has already been tested successfully.

The owner's clarification defines catchment as an experience-acquisition pathway, not merely an audience/distribution metric:

**Use → encounter → record → accumulate → validate → select → translate/adapt → propose upstream → review/incorporate → use again.**

The English project is the initial accumulation point for experiences generated by its user population. Capture does not imply that every experience is reusable, selected, or suitable for upstream contribution. Upstream pull-request acceptance is a separate decision. The English project retains its own experience and provenance whether upstream accepts, rejects, delays or does not respond to a proposal.

This resolves the distribution-intent dependency recorded in Checkpoint 09 at the level of project direction. It does **not** select a concrete package layout, branch/path installation route, metadata correction, release mechanism or automation design.
