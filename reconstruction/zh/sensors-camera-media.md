## 2. 文档角色与内部结构

该文件是经验库中的领域记录，覆盖三个相关但不相同的方向：

1. 高通 SSC 传感器及自动旋转；
2. 高通 Iris/Venus 视频硬解；
3. 相机子系统。

结构仍是经验库通用形式：推荐路线、完成标准、坑、未解决。三个方向的支持前提并不相同，不能仅因它们同处一个文件就视为统一多媒体子系统。

### 传感器与自动旋转

源文件给出一条明确的用户态链：

FastRPC → hexagonrpcd → libssc → iio-sensor-proxy → 桌面合成器。

传感器校准和 registry 配置从 Android 数据分区只读导入，且被明确界定为本机唯一数据，不进入公开仓库。优先复用同 SoC 或同代社区补丁集。

自动旋转验收并非只检查传感器数值，而是要求四种物理方向分别记录五个表面：
- 实际摆放；
- 原始数据；
- SensorProxy 输出；
- 合成器状态；
- 截图。

五者必须一致，并且全新安装后的首次启动不需要人工操作。

故障记录显示，最终桌面行为可能受多个层次影响：安装矩阵、霍尔开关极性、polkit、合成器服务发现、iio-sensor-proxy 重入、hexagonrpcd 方法与缓冲区处理，以及远端处理器启动早于 registry 可读。另有两种明确非传感器原因：Mutter 受平板模式开关控制；simpledrm Unknown connector 不支持旋转。

传感器配置具有启动边界：ADSP sensor PD 每次 ADSP 启动只读一次配置，状态在 hexagonrpcd 重启后仍保留。因此源文件要求每组测试前重新启动、记录启动 ID，不能把重启用户态守护进程当作新状态。

### 视频硬解

路线包括：
- 上游驱动；
- 本机签名固件，并覆盖默认固件名；
- 驱动编译为模块；
- 设备树启用节点；
- 用户态 GStreamer 插件。

完成标准要求逐帧与软件解码一致，并确认应用实际能够使用硬解。故障定位区分 V4L2 队列/流操作与固件消息序列；VP9 和 AV1 也分别记录了不同问题。

视频驱动卸载死锁被标记为【致命】。它不是普通解码输出故障，而是内核锁顺序和设备恢复风险：卸载可能卡住，继而导致正常重启期间设备失联。源文件要求避免无人值守卸载或重绑真实硬件驱动，并通过新的 RAM 启动验证新模块。

### 相机

路线首先确认目标 SoC 是否已有上游 CAMSS 和相机时钟控制器。缺失时，通常需要等待社区或上游支持，首版应明确标记不支持。

完成标准是从真实场景拍出正确图像；出现 `/dev/video*` 不构成完成证据。

故障条目分别区分：
- 芯片 ID 与 vendor 库名对型号判断的证据优先级；
- 取到帧与相机能否通过守护服务、PipeWire 到达应用；
- 自动对焦执行器电压的原厂寄存器证据与猜测的相邻 regulator 档位；
- 相机重启后持续 `-EPIPE` 的现象、可能原因和未定位状态。

## 4. 观察者重构出的对应关系

以下关系是跨内容观察得到的对应，不是源文件定义的统一模型：

- **用户入口的分层链路：**传感器经 SensorProxy 和合成器到达桌面；相机经守护服务和 PipeWire 到达应用。底层成功不等于用户入口可用。
- **新鲜状态与证据有效性：**ADSP sensor PD 的配置只在每次 ADSP 启动时读取，因此重启 hexagonrpcd 不等同于重新启动测试状态。这与 Pattern D 对应，但具体机制来自本领域文档。
- **本机证据与跨设备复用边界：**社区补丁和相邻 SoC 平台数据只能作为起点；固件消息格式、registry、校准和执行器电压仍需本机证据。
- **时序与生命周期：**远端处理器可能早于 registry 可读而启动；合成器服务发现和登录时的策略检查影响旋转；守护进程重启不一定清除 ADSP 传感器状态。
- **多层证据：**物理摆放、原始读数、代理输出、合成器状态和截图是不同观察面。视频验收也区分 V4L2 调用、固件消息、解码帧和应用使用。
- **恢复安全：**视频驱动卸载可能造成内核死锁并破坏正常重启路径。RAM 启动验证和禁止无人值守卸载，是测试期间保留恢复路径的约束。

这些对应关系有助于比较不同子系统的证据和操作边界，但不能据此声称源文件已经定义共同架构。

## 5. 明确未解决与证据边界

源文件明确列出的未解决事项：
- 新 SoC 的相机子系统上游支持；
- 自动对焦；
- 录像。

此外，相机 pipeline 在重启后持续返回 `-EPIPE` 的问题标为“未定位”，并且只给出可能原因。不能将其提升为已确认根因。

其他未建立的内容：
- 相机路线说明先检查 CAMSS 支持，但未提供在已有支持条件下的完整 bring-up 流程。
- 传感器路线以桌面合成器为末端；相机路线要求到达实际应用入口。源文件没有把两者统一为同一验收模板。
- 视频路线指出需要 GStreamer 插件，但没有列出包、插件版本或详细用户态配置步骤。
- 对其他用户设备上的传感器导致远端处理器复位，源文件只给出关闭开关和收集日志的规避方式，没有完整根因。
- Iris 卸载死锁所对应的上游审查补丁是否已经合并，源文件没有说明。

这些边界保留为未知，不以外部多媒体或内核知识补齐。
